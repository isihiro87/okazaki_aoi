## 構成

```
LINE 友だち
   │  テキストメッセージ
   ▼
LINE Messaging API（Webhook）
   │  POST /api/line/webhook
   ▼
aoi（Next.js / Vercel）
   ├─ 署名検証（X-Line-Signature）
   ├─ 発言者の区分を判定（members/{LINEユーザーID}）← 未登録なら「未会員」
   ├─ Firestore のベクトル検索（findNearest）で、その区分が読めるレイヤーだけ検索
   ├─ OpenAI で回答生成
   └─ Messaging API の reply で返信
```

Webhook の実体は **`aoi` 側** にある。`official_line` は静的サイトなのでサーバー処理を持てない。

| 役割 | 場所 |
|------|------|
| Webhook ルート | `aoi/src/app/api/line/webhook/route.ts` |
| Messaging API クライアント・署名検証 | `aoi/src/lib/line/client.ts` |
| 区分ごとの閲覧レイヤー・応答方針 | `aoi/src/lib/access/policy.ts` |
| 会員の判別 | `aoi/src/lib/members/repository.ts`（Firestore `members`） |
| ナレッジ資料 | `aoi/data/` |
| リッチメニュー・LIFF登録フォーム | `official_line/line/` |

### ⚠ デプロイ先を `okazaki-aoi.vercel.app` にしないこと

`aoi` は静的サイトとは**別の Vercel プロジェクト**として、**別ドメイン**に置く。

`okazaki-aoi.vercel.app` は `official_line/`（静的サイト）の本番ドメインで、次の4つが乗っている。
ここに `aoi` をデプロイすると全部が同時に止まる。

| 乗っているもの | 上書きすると |
|---|---|
| 公式サイト（未会員への入口） | 消える |
| リッチメニュー「講話スケジュール」`/#schedule` | リンク切れ |
| リッチメニュー「会場アクセス」`/#access` | リンク切れ |
| LIFF 会員登録フォーム `/line/liff-register/` | 登録できなくなる |

**Webhook URL は会員の目に触れない。** LINE Developers の設定欄に入れるだけなので、
`aoi-chat.vercel.app` のような素っ気ない名前で構わない。

## 2. aoi に環境変数を設定

`aoi/.env.local`（ローカル）と Vercel のプロジェクト設定（本番）の両方に入れる。
全項目は `aoi/.env.example` を参照。

```
# Firestore（サービスアカウントJSONを1行にして貼る）
FIREBASE_SERVICE_ACCOUNT={"project_id":"...","client_email":"...","private_key":"..."}

# 生成モデル
LLM_PROVIDER=openai
OPENAI_API_KEY=（OpenAIのAPIキー）
OPENAI_CHAT_MODEL=gpt-5.6-luna

# LINE
LINE_CHANNEL_SECRET=（チャネルシークレット）
LINE_CHANNEL_ACCESS_TOKEN=（チャネルアクセストークン）
LINE_VERBOSITY=standard
```

`LINE_VERBOSITY` は回答の詳しさ。`concise` / `standard` / `detailed` から選ぶ。
LINEは画面が狭いので、長すぎると感じたら `concise` にする。

### ローカルと Vercel で1箇所だけ違う

Firestore の鍵の渡し方だけが異なる。**ここを取り違えると必ず詰まる。**

| | 使うもの |
|---|---|
| ローカル | `GOOGLE_APPLICATION_CREDENTIALS=./serviceAccount.json`（鍵ファイルを置く） |
| **Vercel** | **`FIREBASE_SERVICE_ACCOUNT`（JSONを1行で貼る）** |

`serviceAccount.json` は `.gitignore` 済みで**リポジトリに乗らない**ため、Vercel 上に存在しない。
`.env.local` をそのままコピーして `GOOGLE_APPLICATION_CREDENTIALS` を残すと、
`Unable to detect a Project Id in the current environment` で 500 になる。

1行JSONは次で作れる（出力先は `tmp/` なので git に乗らない）。

```bash
cd aoi
node -e "const fs=require('fs');fs.writeFileSync('tmp/FIREBASE_SERVICE_ACCOUNT.txt',JSON.stringify(JSON.parse(fs.readFileSync('serviceAccount.json','utf8'))))"
```

Vercel の Environment Variables は、**Key の欄に `.env` 形式の複数行をまとめて貼ると自動で分解**される。
1つずつ入力しなくてよい。ただし**長い値（APIキー等）が落ちることがあるので、保存後に一覧で件数を確認**すること。

> ⚠ **環境変数は保存しただけでは反映されない。** Deployments → 最上段の「…」→ Redeploy が必要。

> ⚠ **Supabase の環境変数（`SUPABASE_URL` など）はもう使わない。**
> 2026/08/10 に Firestore へ統合済み。残っていても無視されるが、混乱のもとなので消してよい。

## 3. ナレッジをデータベースへ投入

```bash
cd aoi
npm run check:llm         # 生成モデルの疎通（鍵とモデルIDの確認）
npm run check:knowledge   # 投入前チェック（DB・APIは呼ばない）
npm run seed:knowledge    # 実際に投入（OpenAI 埋め込みAPIを消費）
```

**名簿を入れずに始める場合**は `:public` を付ける。`data/member/`（名簿・委員会・
ゲスト来訪履歴・会員動向）を除いた4層だけが入る。

```bash
npm run check:knowledge:public
npm run seed:knowledge:public
```

後から `npm run seed:knowledge` を実行すれば名簿も追加できる。
逆に、一度入れたものは除外しても消えない（スクリプトが警告する）。消すなら Firestore コンソールで。

### 3-1. 複合インデックスを3つ作る（投入前・必須）

ベクトル検索用の1つだけでは足りない。**会話の継続と履歴取得にも複合インデックスが要る**ため、
これを作らないと LINE で2通目からエラーになる。

| コレクション | フィールド | 用途 |
|---|---|---|
| `knowledge_chunks` | `layer` 昇順 ＋ `embedding` ベクトル（1536次元・COSINE） | ナレッジ検索（`findNearest`） |
| `conversations` | `sessionId` 昇順 ＋ `updatedAt` 降順 | 送信元から会話を引き当てる |
| `messages` | `conversationId` 昇順 ＋ `createdAt` 降順 | 直近の履歴を読む |

コンソールで作る手順は `aoi/scripts/README.md` §2。`gcloud` があるならコマンドが速い。

```bash
P=aoi-rinri-58275
gcloud firestore indexes composite create --async --project=$P \
  --collection-group=knowledge_chunks --query-scope=COLLECTION \
  --field-config=order=ASCENDING,field-path=layer \
  --field-config=field-path=embedding,vector-config='{"dimension":"1536","flat":"{}"}'
gcloud firestore indexes composite create --async --project=$P \
  --collection-group=conversations --query-scope=COLLECTION \
  --field-config=order=ASCENDING,field-path=sessionId \
  --field-config=order=DESCENDING,field-path=updatedAt
gcloud firestore indexes composite create --async --project=$P \
  --collection-group=messages --query-scope=COLLECTION \
  --field-config=order=ASCENDING,field-path=conversationId \
  --field-config=order=DESCENDING,field-path=createdAt

gcloud firestore indexes composite list --project=$P --format="table(name.basename(),state)"
```

`--async` を付けないと構築完了まで待って固まる。3つとも `READY` になってから使うこと。

## 4. Webhook URL を登録

「Messaging API設定」タブ → Webhook URL に設定する。

```
https://＜aoiのデプロイ先ドメイン＞/api/line/webhook
```

- 「Webhookの利用」を **オン**
- 「検証」ボタンで成功すること（署名付きの空イベントが送られ、200 が返る）
- ブラウザで同じURLを開くと `{"ok":true,"service":"aoi line webhook","configured":true}` が返る。
  `configured` が `false` なら環境変数が未設定

## 5. 自動応答メッセージを止める

「Messaging API設定」→「LINE公式アカウント機能」から LINE Official Account Manager を開き、
**応答設定** を次のようにする。これをしないと定型文とAI応答が二重に届く。

| 項目 | 設定 |
|------|------|
| 応答モード | Bot |
| あいさつメッセージ | オフ（Webhookの `follow` イベントで送るため） |
| 応答メッセージ | **オフ** |
| Webhook | **オン** |

> あいさつメッセージを LINE 側の機能で送りたい場合は、逆に `route.ts` の `follow` 分岐を削り、
> `official_line/line/あいさつメッセージ.md` の文面を Official Account Manager に登録する。

## 6. 誰に何を答えるか（区分の登録）

**既定は全員「未会員」**。Firestore の `members` コレクションに登録された人だけ、区分が上がる。

```
members/{LINEユーザーID}      ← ドキュメントIDは U から始まる33文字
  { role, name, company, position, committee, committeeRole, kaiName, district, active }
```

| 区分 | 読めるレイヤー |
|---|---|
| `guest`（未会員・既定） | official |
| `visitor`（見学者） / `former`（退会者） | official, history |
| `other_kai`（他単会） | official, prefecture, history |
| `member`（会員） | official, prefecture, local, history |
| `officer`（役員） / `executive`（三役） | 上記 + **member** |

**`member` レイヤー（名簿・ゲスト来訪履歴・会員数推移）は役員以上しか読めない。**
未登録の人には、そもそも問い合わせ自体が飛ばない（`retriever.ts` は許可レイヤーだけを個別に検索する）。
照会が失敗したときも `guest` に倒れるので、事故の向きが安全側になっている。

`role` を入れ忘れても、`position` に「専任幹事」などが入っていれば役員として補正される
（`members/repository.ts` の `inferRole`）。明示した `role` のほうが強い。

LINEユーザーIDは、LIFF登録フォーム（`official_line/line/liff-register/`）の送信データか、
Webhook のログから拾う。

## 動作仕様

| 受信 | 挙動 |
|------|------|
| テキストメッセージ | ナレッジ検索 → 回答を返信 |
| `リセット` / `reset` / `最初から` | 会話履歴をリセット |
| 友だち追加（follow） | 使い方の案内を送信 |
| 画像・スタンプ・音声など | 「テキストでご質問ください」と返信 |

- **会話の継続**: 送信元ID（`user:` / `group:` / `room:`）を `conversations` の `sessionId` に持たせ、
  直近6時間以内のやりとりは同じ会話として文脈を引き継ぐ
- **グループトーク**: 個人を特定できないことがあるため、その場合は「未会員」扱い（＝公式レイヤーのみ）
- **入力中表示**: 1対1トークでは回答生成中に「入力中」を表示する
- **長い回答**: LINEの上限5,000文字を超える場合は改行位置で最大5通に分割
- **返信失敗時**: replyToken 失効時は push メッセージで送り直す
- **エラー時も 200 を返す**: LINE の再送ループを避けるため

## トラブルシューティング

立ち上げ時に実際に踏んだものを上に置いてある。

| 症状 | 確認すること |
|------|-------------|
| `GET /api/line/webhook` が `configured:false` | LINEの2つが Vercel に無い。**入れた後に Redeploy したか** |
| `Unable to detect a Project Id` | Vercel に `GOOGLE_APPLICATION_CREDENTIALS` が残っている。消して `FIREBASE_SERVICE_ACCOUNT` を使う（§2） |
| `Missing OPENAI_API_KEY` | まとめ貼りで長い値だけ落ちることがある。一覧に有るか、値が途中で切れていないか |
| 「その情報は登録されていません」ばかり | インデックス3つが `READY` か（§3-1）。`seed` 済みか |
| 2通目からエラーになる | `conversations` / `messages` のインデックス漏れ（§3-1） |
| 回答に `**` が見える | `splitForLine` が装飾を落とす。古いビルドなら Redeploy |
| 検証ボタンが 401 | `LINE_CHANNEL_SECRET` がチャネルシークレットと一致しているか |
| 検証ボタンが 500 | 環境変数が Vercel 側に設定されているか（`GET /api/line/webhook` の `configured`） |
| 返信が来ない | 応答メッセージがオフ、Webhookがオンになっているか |
| 定型文だけ返る | 応答モードが Bot になっているか |
| 「その情報は登録されていません」ばかり | `seed:knowledge` が実行済みか。**ベクトルインデックスが作られているか** |
| 役員なのに一般的な回答しか返らない | `members/{LINEユーザーID}` が登録されているか。IDが正しいか |
| モデルが `model_not_found` | `OPENAI_CHAT_MODEL` のID。`npm run check:llm` で確認 |
| タイムアウトする | Vercel の関数実行時間上限。`route.ts` の `maxDuration` は60秒に設定済み |

## 「お問い合わせ」はAIに通さない

リッチメニューの「お問い合わせ」を押すと `お問い合わせ` という文字が送られます。
**この言葉だけは AI に投げず、決まった案内文をすぐ返します**（`aoi/src/app/api/line/webhook/route.ts` の `CONTACT_KEYWORDS`）。

理由は、「お問い合わせ」の4文字では何を聞きたいのか分からないため。
AIに投げても当てずっぽうの答えになるので、代わりに「そのまま聞いてください」と案内し、
次のひとことを待ちます。RAGの検索も生成もしないので**返信は即時**です。

返す内容は「まずAIが分かる範囲ですぐ答える／分からないことは担当の者が後ほど確認して連絡する」。
文面を変えるときは `CONTACT_MESSAGE` を直してください。

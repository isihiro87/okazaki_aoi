# ゲスト進捗ボード（公式LINEから見る・変える）

ゲストさんの進み具合を、**担当の役員だけ**が公式LINEから確認・更新できる画面です。
朝のMS直後に、片手で開いて押して閉じられることだけを狙っています。

---

## できること

| | |
|---|---|
| 見る | ゲスト名・会社・紹介者・初回来訪日・いまの進み具合 |
| 変える | 進み具合／次にやること／担当／メモ |
| 絞る | **要フォロー**（まだ結論が出ていない人）／**自分の紹介**／すべて |

進み具合は6つです。**声かけ中 → 参加予定 → 参加した → 2回目以降 → 入会**（または**見送り**）。

「2回目以降」を独立させているのは、**ゲストの2回目来場が入会の先行指標**だからです
（`docs/16_R9運営設計/05_R9運営方針.md` §10）。1回来た人と2回来た人は、別のものとして数えます。

---

## ⚠ 個人情報の扱い ―― ここが設計の要です

ゲスト表には**氏名・会社名**が入ります。会の方針は「**会員・ゲストの氏名をLINE配信に載せない**」です
（トーク履歴は端末に残り、機種変更やスクリーンショットで簡単に外へ出るため）。

この画面はその方針と矛盾しません。**LIFFはメッセージではなく、LINEの中で開くウェブページ**だからです。
トーク履歴には何も残りません。

そのうえで、次の3つで守っています。

1. **IDトークンをサーバー側で検証する。**
   画面から送られてくるユーザーIDは信用せず、`aoi` が LINE の `verify` API に問い合わせて本人確認します。
   URLを知っているだけの人がデータを取ることはできません。
2. **役員以上だけが通る。**
   Firestore の `members` に登録された役職で判定します。
   **正副三役／監査／顧問／幹事／各委員会リーダー・サブ**（`canUseGuestBoard`）。
   **組織図・名簿（`canViewRoster`）と同じ範囲**です。役員用リッチメニューに2つが並んでいるので、
   片方だけ狭いと「ボタンは見えるのに押すと断られる」ことになるため揃えました（2026/8/31）。
   チャットボットが個人情報レイヤーを読めるかどうかと**同じ判定**を使っているので、
   許可リストを二重に持ちません。片方だけ古くなる事故が起きません。
3. **配信するときは件数とリンクだけ。**
   「要フォロー3名」＋この画面へのリンク、という送り方をします。**氏名はメッセージに書きません。**

> ⚠ **メールアドレス・電話番号はこの画面に出しません。** 連絡先はゲスト申込フォームの回答スプレッドシート側に置いたままにします。
> 表示する項目を増やすときは、それが漏れて困るものかどうかを先に考えてください。

## しくみ

```
LINEアプリ
  └ LIFF（この画面・Vercelの静的ページ）
       │  POST { idToken, action, ... }
       ▼
  aoi アプリ  /api/guests
       │  ① LINE に IDトークンを検証させる
       │  ② members を引いて役員以上か確かめる
       ▼
  Firestore  guests コレクション
```

| ファイル | 役割 |
|---|---|
| `aoi/src/app/api/guests/route.ts` | 受け口。認証とCORS |
| `aoi/src/lib/guests/repository.ts` | Firestore の読み書き |
| `aoi/src/lib/line/verifyIdToken.ts` | IDトークンの検証 |
| `aoi/src/lib/access/policy.ts` | 誰が役員かの判定（既存） |

> **Apps Script は使いません。** 当初 GAS で作りましたが、Google がアカウント側で承認をブロックし、
> 最小権限のスクリプトすら実行できませんでした。経緯は `../gas/Guests.gs` の冒頭に残してあります。

## セットアップ

### 1. aoi 側の環境変数

Vercel（と手元の `.env.local`）に追加します。

| 変数 | 値 |
|---|---|
| `LINE_LOGIN_CHANNEL_ID` | LINEログインチャネルの**チャネルID**（LIFFが乗っているチャネル） |
| `LIFF_ALLOWED_ORIGINS` | 既定の `https://okazaki-aoi.vercel.app` 以外から開くときだけ（カンマ区切り） |

Firestore の資格情報（`FIREBASE_SERVICE_ACCOUNT`）は、チャットボットで使っているものをそのまま使います。

### 2. LIFF を作る

1. LINE Developers で LIFF アプリを追加
   - エンドポイントURL：`https://okazaki-aoi.vercel.app/line/liff-guests/`
   - サイズ：**Full**
   - スコープ：`profile` と **`openid`**（← IDトークンに必要。忘れやすい）
2. 発行された LIFF ID を控える

### 3. 画面につなぐ

`js/app.js` の冒頭2か所を差し替えます。

```js
const LIFF_ID = "…";        // 手順2のLIFF ID
const API_ENDPOINT = "https://＜aoiのデプロイ先＞/api/guests";
```

### 4. 自分を役員として登録する

Firestore に **`members/{LINEユーザーID}`** というドキュメントを作ります。

```
name: "石本 大貴"
role: "executive"      ← executive（三役）または officer（役員）
position: "専任幹事"
```

**自分のLINEユーザーIDは、この画面が教えてくれます。**

1. LIFF の URL（`https://liff.line.me/{LIFF ID}`）から開く
2. まだ登録されていないので「担当者のみが見られます」と出て、**その下にご自身のIDが表示されます**
3. そのIDをドキュメントIDにして `members` に追加する
4. もう一度開くと一覧が出ます

他の役員にも「一度開いて、出てきたIDを送ってください」と伝えれば足ります。
表示されるのは**本人自身のID**だけなので、他の人の情報は出ません。

> `members` はチャットボットが役割判定に使っているコレクションと同じです。
> ここに登録すると、**AIへの質問も役員向けの答え方に変わります。** 一石二鳥です。

### 5. ゲストを入れる

`guests` コレクションにドキュメントを追加します。最低限 `name` があれば表示されます。

```
name: "名古 承悟"          （必須）
company: "ヤマナ運輸(株)"
referrer: "神道 裕"
firstVisit: "2026-07-30"
status: "参加した"
```

来訪履歴の読み物版は `aoi/data/member/aoi-guests.md` にあります。そこから写せます。

### 6. リッチメニューから開く

リッチメニューのボタンに LIFF の URL を割り当てます。
**全員に見えるメニューに置いても構いません** — 役員以外にはデータが返りません。

## 使い方（役員向けの説明文・そのまま配れます）

> **ゲスト進捗の画面ができました。**
> リッチメニューの「ゲスト進捗」から開けます。
>
> ・**要フォロー**を押すと、まだ結論が出ていない方だけが出ます
> ・お名前をタップすると、進み具合を変えられます
> ・「次にやること」を一行書いておくと、次の人が迷いません
>
> 見られるのはゲスト対応の担当者だけです。他の方が開いても中身は表示されません。

## 運用のコツ

- **「様子見」と書かない。** 次にやることを一行書く（`05_R9運営方針.md` の運用ルールと同じ）
- **金曜に「要フォロー◯名」だけをLINEへ流す。** 氏名は書かず、この画面へのリンクを添える
- **入会・見送りが付いた人は要フォローから自動で消えます。** リストが伸び続けないので、開くのが億劫になりません
